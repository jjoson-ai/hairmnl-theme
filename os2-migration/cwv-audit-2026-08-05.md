## 3. Ranked opportunities

### T1 — Consolidate Google Tag Manager containers *(biggest single lever)*
**Evidence:** four separate gtag payloads load per page — `G-9LV7TG5ZH7` **twice** (179KB each),
`GT-5R3FN5JG` (141KB), `AW-611729126` (151KB). ~650KB and **2950ms of main thread**. Unused-JS
attributes 117+71+64+58 KB of pure waste to these.
**Action:** consolidate to a single GTM container loading GA4 + Ads + the rest as tags inside it;
eliminate the duplicate `G-9LV7TG5ZH7` load outright (that one is free — it is a straight duplicate).
**Owner:** GTM admin, no theme code. **Risk:** low (tag config, reversible).

### T2 — Scope the per-page app scripts to the pages that need them
- **Judge.me** 1224ms / 224KB on *every* page including home and blogs. Already filed as bd `mk47`.
- **LDT gift-wrap** 905ms / 839KB (168KB single script) sitewide for a cart-only feature.
- **BOGOS free-gifts** ~850ms across three scripts.
- **Searchanise** 355ms; **jQuery 3.7.1 from a Microsoft CDN** 151KB/114ms — check whether anything
  still needs jQuery at all.
**Action:** move each to a theme-app-extension block gated to the templates that use it, or lazy-load
on interaction (the store already has two proven defer-guard families for exactly this — see
`CLAUDE.md`). **Risk:** medium — each needs a smoke test; do them one at a time.

### T3 — DOM size on home and brand
**Evidence:** home renders **11,877 DOM elements**, brand 6,967. Lighthouse flags >1,400 as
excessive; the practical target is <2,000. This directly drives the Style & Layout (1995ms) and
Rendering (1255ms) buckets, and it is why "element render delay" dominates LCP.
**Action:** the brand page ships **24 sections** and 1.4 MB of HTML. Paginate/lazy-mount the
below-fold collection carousels rather than server-rendering all of them.
**Risk:** medium — merchandising-visible.

### T4 — PDP asset sprawl
**Evidence:** 453 requests, 170 scripts, **62 stylesheets** on a single product page.
**Action:** audit which app embeds inject stylesheets on PDP; consolidate the theme's own
per-template CSS chunks. **Risk:** low-medium.

### T5 — First-party quick wins *(cheap, safe)*
- `snippets/css-overrides.liquid` is **unminified: 8.4 KB wasted of 10.5 KB** — it is inlined into
  every page, so this is pure first-paint cost. Minify it.
- **Image delivery: ~150 KB wasted** on oversized collection images (served larger than displayed) —
  8 Davines gift-set images alone.
- 27–62 stylesheets per template; the theme's own chunks can be merged.

### T6 — Architectural risk: the inline/deferred CSS split
This week produced **three** separate CLS bugs from one root cause — a rule needed at first paint
that lives only in a deferred stylesheet (`dh8x` brick containing-block, `wscl`'s own `6ch`
font-relative reservation, `nahn.4` blog rules). All three are now fixed, but the pattern will
recur with every new section.
**Action:** add a CI check that flags geometry-affecting rules (`position`, `display`, `width`,
`height`, `flex`, `grid`, font-size) whose selectors appear in server-rendered markup but are absent
from `critical-css.liquid`. This is the same class of guard as the existing `check-overlay-css.py`
and `check-snippet-wiring.py`.

## 4. What NOT to spend effort on

- **The mobile PSI score (33–47).** It is a lab artifact. Field LCP p75 is 1.8s and 87% good. Fixing
  the score would require re-architecting for a simulated environment that does not match reality.
- **TTFB.** Lab shows 22–54ms; field p75 707ms phone is Shopify platform + geography (PH), and it is
  already the metric that improved most on P8 (+9.7pt). Nothing theme-side to win here.
- **Chasing desktop day-1 LCP/FCP dips.** n=326–599, launch week. Re-read at 28 days.

---

## 5. The one thing to actually watch

**CrUX turns over ~2026-09-02**, when the 28-day window becomes majority-P8. That is the real
P8-vs-P6 verdict. The day-1 beacon says mobile is up on every metric, so the expectation is a hold
or a small gain — but confirm it, and specifically confirm CLS holds the +6.3pt (that gain is the
`dh8x`/`wscl`/`nahn.4` fixes landing).

Priority order if you only do three things: **(1) collapse the GTM containers, (2) scope Judge.me +
LDT gift-wrap off the pages that don't use them, (3) cut the home/brand DOM count.** Together those
target roughly 5s of the 9.75s of third-party main-thread time and the largest Style/Layout driver —
which is what INP, the weakest field metric, is made of.

# --- FALSE POSITIVE: the lint reduces a qualified selector to its rightmost class token, so it
# --- believes an ancestor is positioned when the qualifier never actually matches this markup.
image-overlay/homepage-slideshow    3q2e   FALSE POSITIVE. The overlay that actually ships (section-slideshow.liquid:57) is a child of `.slideshow__slide … section--image`, and critical CSS declares `.section--image{position:relative}` — it already has its containing block. The lint only names `.homepage-slideshow` because of a SECOND occurrence at :102 inside `{% if section.blocks.size == 0 %}`, the theme-editor onboarding placeholder, which is unreachable: all 18 section-slideshow instances have 3-6 blocks and are disabled:true.

# --- SAFE: the element genuinely has no containing block at first paint, but it cannot shift
# --- because it paints nothing.
image-overlay/cart__empty           3q2e   SAFE. The chain .wrapper -> .cart__empty really is unpositioned at first paint, but the element paints nothing: critical CSS never DEFINES `--bg` (19 var(--bg) reads, zero definitions, no @property), so `background-color:var(--bg)` is invalid-at-computed-value-time and falls back to transparent; the div is server-rendered empty with no border, shadow, image or content-bearing pseudo. FRAGILE, not broken: if anyone later adds a `:root{--bg:...}` block to critical-css.liquid this becomes an opaque full-viewport rectangle at z-index 2. The cheap hardening is `.cart__empty{position:relative}` — byte-consistent with theme-core.css:14654 and rendering-neutral.
item--loadbar/cart__items__row      3q2e   SAFE. Server-rendered with an inline `style="display: none;"` (cart-line-items.liquid:7), and NO stylesheet anywhere declares `display` for `.item--loadbar`, so the inline rule wins at first paint and neither the bar nor its background-carrying `:before` generates a box. A display:none element cannot shift.
tabs__arrow/tabs__head              3q2e   SAFE. Every `.tabs__arrow` in the theme ships with the `is-hidden` class, and critical CSS carries `.is-hidden{visibility:hidden;max-height:0;overflow:hidden;opacity:0}` unconditionally with nothing re-asserting visibility or opacity. The lint is structurally right that `.tabs__head` is uncovered (the critical build kept only the `.tabs-wrapper` half of the deferred `.tabs-wrapper,.tabs__head` selector list) — but an invisible element contributes no shift. Optional belt-and-braces mirror `.tabs__head{position:relative}` is byte-safe if ever wanted.
icon/height                         3q2e   SAFE (medium confidence). `.icon{height:1em}` is byte-identical to its deferred rule — only the inherited em basis moves (html 16px -> body 13.14426px) because critical CSS omits the body font-size. Every first-viewport `.icon` site is either px-pinned in critical CSS byte-identically (`.navlink .icon`, `.header__mobile__* .icon`, `.media__zoom__icon svg`) or sits in a critically height-pinned box (`.tousled-header__wrapper .mobile-menu-box{height:45px}`), leaving <=3px residuals. Do NOT "fix" by adding font-size to `.icon`: `.share__link .icon{1.2em}`, `.pagination-custom .icon{.45em}` and `.announcement__bar--icon .icon{1.1em}` all resolve against the inherited context, so pinning it would permanently change live rendering.

# --- REAL, but the remedy is a sitewide first-paint typography change, not a position mirror.
# --- Deliberately NOT folded into the 3q2e position-mirror change; tracked as its own ticket.
collection__nav/height              3q2e   REAL, deferred to a follow-up ticket. `height:3.3em` on a bordered, server-rendered nav that is above the fold on every collection page; critical CSS omits the body font-size AND font-family, so first paint is UA serif at 16px (3.3em = 52.8px) and settles to 13.14426px (43.4px) — a ~9.4px reflow. The only safe fix mirrors the deferred body font cascade VERBATIM AND IN FULL (theme-core.css:6799 unconditional + the @media 480px vw-interpolated block + the @media 1400px block); mirroring only the unconditional block would change rendering at every viewport >=480px. Must be body-scoped: critical CSS deliberately keeps `input,select,textarea{font-size:16px}` as the iOS zoom-on-focus guard. That fix will NOT silence this row — RULE 2 keys on the flagged class having its own font-size, and `.collection__nav` intentionally has none.
icon/width                          3q2e   REAL but low-magnitude; same root cause and same follow-up ticket as collection__nav/height (missing body font-size in critical CSS). Residuals found: `.cart__remove__icon` on /cart (unsized by any sheet, 2.86px), plus the `.popout__toggle` sort icon and the mobile search button (1.33px each, pinned by 12px accent rules that a body mirror does NOT reach). One larger case is conditional on catalogue data and is filed separately: `.media__thumb .icon` is position:absolute + 20x20 ONLY in the deferred sheet, so on a PDP whose product has video/3D media the icon starts as an in-flow 1em box overflowing the 60x60 thumb.
